# Бот для расчёта тренировок по бадминтону

![Snowflakes bot](assets/snowflakes-bot.png)

Telegram-бот для участников одной общей группы: участники, гости, локации, время игры, воланы,
оплата корта, расчёт переводов и отметки полных/частичных оплат. Интерфейс на русском.

## Запуск

Нужен Python 3.8+ на macOS/Linux (для нового сервера рекомендуется Python 3.12+).
Внешних Python-зависимостей нет. SQLite входит в стандартную библиотеку.

1. Создайте отдельного бота в [@BotFather](https://t.me/BotFather), команда `/newbot`.
2. В папке проекта выполните `cp .env.example .env`.
3. В `.env` заполните `TELEGRAM_BOT_TOKEN` и `ADMIN_IDS`.
   ID — число, не `@username`. Можно узнать свой ID у [@userinfobot](https://t.me/userinfobot).
   Здесь задаются владельцы бота, которым разрешена привязка группы и резервный доступ.
   Несколько владельцев перечисляются через запятую. Обычных участников добавлять не нужно:
   их членство в подключённой группе проверяется через Telegram при каждом обращении.
   Токен не отправляйте в групповой чат и не добавляйте в Git.
4. Проверьте настройки и запустите:

```sh
python3 -m badminton --check
python3 -m badminton
```

Проверка `--check` проверяет формат настроек без сети. При обычном запуске бот проверяет
токен через Telegram. Откройте личный чат с ботом и отправьте `/start`.
Процесс должен продолжать работать; при выключении/сне компьютера бот недоступен.

Для постоянной работы на сервере с Docker Compose:

```sh
docker compose up -d --build
docker compose logs -f
```

Для работы только через чат порты и публичный домен не нужны: бот использует long polling по HTTPS.
Запускайте только один экземпляр на токен. Если у бота настроен webhook,
сначала отключите предыдущую интеграцию; приложение не удаляет webhook самостоятельно.

## Telegram Mini App

Веб-интерфейс на русском использует ту же базу, справочники, расчёты и очередь публикаций,
что и чат бота. Доступны создание и редактирование тренировок, сохранённые участники и гости,
часы и воланы, несколько плательщиков корта (включая неиграющих), предварительный расчёт,
фиксация, полные и частичные оплаты, отмена последней отметки, закрытие и повторное открытие,
история и публикация итогов в группе. Привязка группы остаётся командой `/bind` владельца
в самой группе; инструкция есть в разделе «Группа» мини-аппа.

Интерфейс адаптирован для телефона и компьютера, поддерживает светлую и тёмную тему Telegram.
Установка Node.js и сборка фронтенда для запуска не нужны.

### Подключение

**Существующий деплой Railway:** проект `snowflakes-share-bot`, окружение `production`,
сервис `bad-bot`. Адрес Mini App: <https://bad-bot-production.up.railway.app>.
Для него используются `MINIAPP_URL=https://bad-bot-production.up.railway.app`,
`MINIAPP_HOST=0.0.0.0`, `MINIAPP_PORT=8080`; домен направлен на порт `8080`.
HTTPS обслуживает Railway, отдельный Caddy не нужен. База остаётся в
`/app/data/badminton.sqlite3` на существующем томе `bad-bot-volume`.
Не запускайте второй экземпляр бота с тем же токеном.

Для самостоятельного размещения вне Railway:

1. Направьте отдельный домен, например `badminton.example.com`, на сервер с ботом.
2. Настройте HTTPS reverse proxy на `127.0.0.1:8080`. Например, Caddy:

   ```caddyfile
   badminton.example.com {
       reverse_proxy 127.0.0.1:8080
   }
   ```

3. Добавьте в `.env`:

   ```dotenv
   MINIAPP_URL=https://badminton.example.com
   MINIAPP_HOST=127.0.0.1
   MINIAPP_PORT=8080
   ```

   Укажите свой реальный домен. Адрес должен вести на корень приложения, без пути.
   В Docker Compose адрес прослушивания внутри контейнера уже задан как `0.0.0.0`,
   а порт опубликован только на loopback хоста. Пример Caddy предполагает запуск Caddy
   на хосте; для отдельного контейнера прокси настройте общую Docker-сеть.

4. Выполните `python3 -m badminton --check` и перезапустите бота
   (для Docker: `docker compose up -d --build`). В личном чате появится кнопка меню
   **Тренировки**, открывающая Mini App. При запуске бот устанавливает её через
   `setChatMenuButton`. Пустой `MINIAPP_URL` отключает веб-сервер; ранее установленную
   кнопку при необходимости сбросьте в BotFather.

Без настроенного домена приложение ещё не доступно пользователям Telegram.
HTTP-сервер рассчитан на работу за HTTPS reverse proxy; не публикуйте его порт напрямую.
Проверка входа следует [протоколу Telegram Mini Apps](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app):
подпись `initData`, срок до 24 часов и свежая проверка членства в группе на каждый запрос.
При истечении срока нужно закрыть и заново открыть мини-апп. При открытии обычной ссылки
в браузере данные не выдаются — войдите через Telegram.

Операции выполняются транзакционно. Повтор запроса с тем же идентификатором не повторяет
платёж, а устаревшая версия данных требует обновления. Если связь оборвалась во время
сохранения, повторите действие либо нажмите кнопку обновления, чтобы проверить результат.
Публикация отправляется существующим процессом бота; сообщение об успешной отправке
или ошибке приходит в личный чат, а интерфейс подтверждает только постановку в очередь.

### Проверка Mini App

`python3 -m unittest discover -v` включает API, подпись Telegram, права, повторные запросы,
устаревшие данные, откат ошибочных изменений и полный финансовый цикл. HTTP-тесты поднимают
сервер только на `127.0.0.1` с временной базой.

Дополнительный браузерный сценарий — `node tests/miniapp_browser.cjs`.
Он требует доступного Node-пакета `playwright` и установленного Google Chrome
(другой канал можно задать через `BROWSER_CHANNEL`). Пакет можно предоставить через
`NODE_PATH`. Сценарий использует отдельную временную базу и тестовую авторизацию,
не читает `.env`, не обращается в Telegram и сохраняет скриншоты в `/tmp/bad-bot-miniapp-*.png`.

## Использование

1. **Новая тренировка**: дата → сохранённая или новая локация → полная стоимость корта.
2. **Участники**: выбирайте из справочника, добавляйте новых или гостей.
   Новый участник сохраняется для следующих тренировок. Гость — только для текущей.
   Telegram-аккаунт участника не нужен. Совпадающее имя в справочнике означает того же
   человека; для тёзок добавьте фамилию или отличительный признак.
3. По умолчанию у каждого **2 часа и 0 воланов**. Нажмите имя для изменения.
   При вводе количества воланов бот запросит цену за штуку, если она ещё не указана.
   Используется стоимость потраченных на тренировке воланов, а не всей упаковки.
4. **Кто оплатил корт**: укажите сумму для одного или нескольких плательщиков.
   Плательщик может одновременно предоставлять воланы, а может вообще не играть.
   Повторный ввод суммы заменяет прежнюю, не прибавляется к ней; 0 убирает оплату.
5. **Рассчитать**: проверьте доли и предлагаемые переводы, затем зафиксируйте расчёт.
6. **Расчёт и переводы**: выберите перевод и отметьте весь остаток или частичную оплату.
   Ошибочную последнюю отметку можно отменить. Бот не выполняет банковские переводы.
7. **Закрыть тренировку** доступно, когда все переводы отмечены. История сохраняется.

Команды: `/start`, `/new`, `/history`, `/poll`, `/polls`, `/cancel`.
«Сегодня» определяется по времени Таиланда (UTC+7).
Десятичные суммы и часы принимаются с точкой или запятой.

## Голосования и перенос состава

В мини-аппе откройте **Голосования → Создать** или отправьте боту `/poll` в личном чате.
В заголовке укажите локацию и одну дату, например `Baam · 26/09` или `SSC 26.09`.
Дата должна быть в формате `дд/мм` или `дд.мм`. Год выбирается ближайший к дате создания
опроса (включая переход декабрь/январь) и показывается перед созданием тренировки.
Если название совпадает с единственной сохранённой локацией в заголовке, она подставится
автоматически; иначе при создании тренировки нужно выбрать локацию.

По умолчанию предложены `19:00-21:00`, `Thinking`, `No`. До публикации можно изменить
заголовок и весь список вариантов (от 2 до 12), по одному ответу в строке.
Кнопка **Опубликовать голосование** отправляет обычный Telegram-опрос в подключённую группу
и её настроенную тему. Без `/bind` публикация недоступна.

Опрос неанонимный, с одним выбранным ответом. В Telegram можно менять и отзывать голос,
добавлять свой вариант, смотреть результаты и имена голосовавших. Эти настройки включены
через [sendPoll](https://core.telegram.org/bots/api#sendpoll). Полученные имена также видны
в разделе «Голосования» мини-аппа и по `/polls`; кнопка обновления получает новые данные.
Для новых возможностей голосований используйте актуальный клиент Telegram.

При нажатии **Новая тренировка** выбирается последнее успешно отправленное ботом
голосование подключённой группы. Если тренировка на его дату уже есть, предлагается
открыть её. При желании остаётся явное создание вручную. Более старое голосование
автоматически вместо последнего не выбирается.

Из последнего опроса переносятся выбравшие `Yes`, `Да`, `19:00-21:00`, `19:00`
или `18:00-20:00`, включая добавленные участниками варианты с таким текстом.
Регистр и любое количество пробельных символов игнорируются даже внутри ответа.
Другие ответы (в том числе другое время) видны в результатах, но автоматически
в состав не включаются. Их можно добавить вручную в тренировке.
Для каждого импортированного игрока сохраняются стандартные 2 часа и 0 воланов;
это можно изменить после создания.

Состав берётся из последних полученных голосов в момент сохранения тренировки.
Отмена голоса и смена ответа учитываются до этого момента; после создания состав
сам по себе не меняется. Повторный импорт на занятую дату блокируется на сервере.
Если Telegram сообщил больше голосов, чем передал боту имён, либо новый вариант
ещё не пришёл, импорт ждёт синхронизации и не создаёт заведомо неполный состав.

Пользователь Telegram связывается с участником по ID. При первом импорте используется
точное совпадение полного имени со свободной записью справочника, иначе создаётся новая.
Разные Telegram ID с одинаковым именем разделяются; у второго к имени добавляется ID.
Проверьте состав перед расчётом, особенно если в справочнике используются сокращённые имена.

Созданные вручную или другим ботом опросы не импортируются. При неопределённом результате
отправки бот не повторяет `sendPoll` автоматически, чтобы не создавать дубликаты:
проверьте группу перед повторным созданием. Ответы сохраняются в SQLite и переживают
перезапуск. Сброс истории тренировок сохраняет голосования и связи Telegram-участников.

При запуске автоматически добавляются общие справочники:

- Участники: Настя, Дима Ск, Дима Си, Андрей Н, Рамиля, Толя, Лена, Маша,
  Саша, Сергей С, Сергей Г, Андрей Г, Дмитро, Серхий, Даша, Натали, Айболит,
  Daniel, Harvest, John.
- Локации: Baam, Grand, SSC.

Повторный запуск не создаёт дубликатов и сохраняет существующие записи.
Эти участники доступны для выбора; состав каждой тренировки задаётся отдельно.

## Публикация в групповой чат

1. Добавьте бота в группу и назначьте администратором. Это нужно для надёжной
   проверки членства через `getChatMember`; дополнительные права удаления сообщений
   или блокировки участников для работы бота не нужны.
2. Со своего аккаунта владельца (`ADMIN_IDS`) отправьте в группе
   `/bind@badminton_share_bot` (если бот переименован, используйте его username).
   В группе с темами отправьте команду в нужной теме. Бот подтвердит привязку в личке.
3. Любой участник группы открывает личный чат с ботом и отправляет `/start`.
   Ему доступны общие справочники и история, создание и редактирование тренировок,
   расчёт, отметки оплат и публикация. Самостоятельной записи на тренировку нет.
4. В личном чате откройте зафиксированный расчёт, нажмите **Опубликовать итог в группе**
   и подтвердите группу назначения.

В группе появятся дата, локация, расходы, стоимость участия каждого и список
«кто → кому → сколько». Частичные/полные оплаты, отмена отметки и закрытие тренировки
обновляют то же сообщение. Большие расчёты разбиваются на несколько частей.
Возврат к редактированию помечает опубликованные суммы как неактуальные до новой фиксации.
Самостоятельной записи нет; все изменения делает организатор в личке.

Привязать группу может только владелец из `ADMIN_IDS`. Обычные сообщения в группе
игнорируются. Одна установка обслуживает одну общую группу; привязка другого чата
после настройки запрещена, чтобы не раскрыть ему историю. Повторный `/bind` в той же
группе позволяет обновить тему публикаций для новых тренировок. Старые публикации
остаются в прежней теме. До нажатия кнопки публикации финансовые данные
в группу не отправляются. Если бот удалён из группы или лишён права отправки,
он сообщит организатору об ошибке. После исправления нажмите **Обновить итог в группе**.

## Общие данные и доступ

История, участники и локации общие для всех участников подключённой группы.
Состояние диалога у каждого своё: одновременное создание разных тренировок не смешивает
поля ввода. Если общие данные изменились, устаревшая операция записи отклоняется
с предложением открыть актуальные данные через `/history` или `/start`.
Это также предотвращает двойную отметку оплаты разными людьми.

Пользователь вне группы и вышедший из неё участник не получают доступ. При ошибке
проверки Telegram доступ не предоставляется. Владельцы в `ADMIN_IDS` сохраняют
резервный доступ, в том числе до подключения группы.

При первом запуске новой версии бот создаёт резервную копию базы рядом с основным
файлом (`*.before-shared-*.sqlite3`) и переносит прежние данные в общую область.
Исторические ID участников и переводы сохраняются; одинаковые записи в справочниках
объединяются без изменения расчётов. При повторном запуске перенос не повторяется.

## Правила расчёта

```text
Расходы на воланы человека = количество × цена одного волана
Все расходы = стоимость корта + расходы на воланы всех участников
Доля человека = все расходы × его минуты / суммарные минуты участников
Баланс = доля − предоставленные им воланы − оплаченный им корт
```

Баланс больше нуля — доплатить, меньше нуля — получить возмещение.
Цена корта добавляется к расходам ровно один раз; его оплаты определяют получателей.
Стоимость корта вводится за всю тренировку, не за час и не за один корт.
Все расходы распределяются пропорционально времени, без деления на временные интервалы.
У одного участника одна цена волана на тренировку. Несколько цен у одного человека
в рамках одной тренировки пока не поддерживаются.

Валюта первой версии — THB. Деньги хранятся в целых сатангах (0,01 бата),
время — в целых минутах. Доли сначала округляются вниз, затем оставшиеся сатанги
добавляются участникам с наибольшими дробными остатками. При равенстве используется
постоянный ID человека. Общая сумма всегда сходится. Переводы строятся детерминированно;
минимальное возможное количество переводов не гарантируется.

Нельзя зафиксировать расчёт с пустым составом, нераспределённой оплатой корта
или ненулевым количеством воланов без цены. Участники могут иметь разное время и цены.
Состав и параметры каждой тренировки независимы.

## Исправления, надёжность и хранение

### Обнуление истории в Railway

Из локальной папки проекта выполните сначала просмотр:

```sh
./scripts/reset-railway-history.sh
```

Команда покажет количество тренировок и связанных записей, ничего не удаляя.
Чтобы действительно обнулить историю:

```sh
./scripts/reset-railway-history.sh --confirm DELETE_ALL_TRAININGS
```

Скрипт использует Railway CLI и ранее подключённый SSH-ключ `~/.ssh/id_ed25519`.
Он явно выбирает `snowflakes-share-bot / production / bad-bot` и запускает код
из локального `badminton/reset_history.py` на сервере — отдельный деплой не нужен.
Если CLI ещё не установлен, установите `@railway/cli` и войдите через `railway login`.

Перед удалением автоматически создаётся проверенная резервная копия на том же диске:
`/app/data/badminton.sqlite3.before-reset-ДАТА-ВРЕМЯ`. Её точный путь выводится в ответе.
Удаляются все тренировки, составы, расходы, расчёты, отметки оплат и ссылки на публикации.
Участники справочника, локации, привязка группы и Telegram offset сохраняются.
Уже отправленные сообщения в Telegram остаются и больше не обновляются.
После сброса обновите мини-апп или отправьте боту `/start`.

Сброс выполняется одной транзакцией. Если в очереди есть сообщения, команда откажется
удалять данные: дождитесь их отправки и повторите. Во время сброса не создавайте
новые тренировки. При ошибке удаления изменения откатываются.

Для локальной базы аналогичная команда:
`python3 -m badminton.reset_history --database data/badminton.sqlite3`;
добавьте `--confirm DELETE_ALL_TRAININGS` только для реального удаления.
Не подменяйте файл рабочей базы резервной копией при запущенном боте.

- До фиксации можно менять состав, время, расходы, дату и локацию.
- После фиксации для изменения исходных данных нужно отменить отмеченные переводы
  и выбрать «Вернуть к редактированию». Закрытую тренировку можно открыть снова.
- Расчёт хранится вместе с конкретными переводами. Оплаты не добавляются к расходам.
- SQLite сохраняет справочники, тренировки, переводы, состояние ввода и очередь ответов.
- Каждое входящее событие обрабатывается в транзакции. Повторная доставка события
  не повторяет денежную операцию. Старые кнопки не работают после перехода к новому меню.
- Ответы сохраняются до отправки и повторяются при сетевых сбоях. В редком случае
  обрыва связи после принятия сообщения Telegram возможен повтор ответа, но не оплаты.
- Управление доступно участникам подключённой группы и владельцам `ADMIN_IDS` в личке.
  В группе доступна только привязка владельцем командой `/bind`; итог публикуется
  по кнопке участника из личного чата.
  Участники не получают автоматических личных сообщений.
- Бот не проверяет банковские поступления: отметки делает организатор.
- Локальная база: `data/badminton.sqlite3`. В Docker — именованный том `bot-data`.
  Для резервной копии остановите бота и скопируйте весь каталог данных/том, затем
  запустите снова. Не удаляйте том через `docker compose down -v`, если нужна история.
- Не меняйте токен на другого бота, сохраняя прежнюю базу: offset относится к одному боту.

## Проверка

```sh
python3 -m unittest discover -v
```

Тесты не обращаются в Telegram и не требуют токена. Проверяются пример из таблицы,
разное время и цены, несколько плательщиков, округление и сохранение баланса,
диалог, восстановление после перезапуска, частичные оплаты, отмена, права доступа,
устаревшие кнопки и повторная доставка событий.

Документация протокола: [Telegram Bot API](https://core.telegram.org/bots/api).
